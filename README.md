# 07-revflow（冲流台）

冲流台 — 正向与冲正流水净额归并：正向装载 → 冲正关联入账 → 净额归并落余额 → 未平/超额隔离 → 流水净额与余额互证。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流，**不是** 质检签发，**不是** 数仓分层建设，**不是** 交班过户。  
**也不是** 收银/退款 CRUD 后台、电商订单、报表 CSV 看板——主链是**流水管道与净额状态**，不是业务单据编辑台。

## 主链

账户登记 → 装载正向流水 → 装载冲正并关联原单 → （可选）声明冲正捆扎 → 跑净额归并（已配平落余额，未平/超额进隔离）→ 互证报告核对「流水净额 vs 账户余额」

## 多腿冲正捆扎（multi_leg_net）

一批冲正可声明同一**捆扎键**，作为同一配平单元「全成或全进未平」：

- **落库形态（择一：独立捆扎表）**：独立捆扎表 `reversal_bundles`（捆状态：待归捆/整捆已归并/整捆已隔离）+ `reversal_bundle_members`（成员冲正键，一笔至多属一捆；声明后为**不可变成员快照**，按捆扎键永远查得全成员，不按流水状态过滤）；隔离项与归并运行冗余 `bundle_key`，落库即可区分捆扎集合与散笔，不依赖请求体数组。
- **半捆收口（择一：全捆预检）**：先以纯预演判定整捆可配平，**预检通过后才允许写任何正式余额；预检失败零落账**。任一腿不满足（无原单/账户不一致/超额）则整捆进未平隔离，好腿标「连带隔离」，正式余额分毫不动，捆状态置「整捆已隔离」。禁止好腿留账、坏腿只改隔离。成员状态 + 余额 + 隔离 + 捆状态 + 分桶证明在同一 SQLite 事务内提交，中途异常整体回滚。
- **捆分桶证明（`bundle_settlement_proofs`）**：基线所无的新增实体。归并运行每处理一捆落一行不可变证明，挂归并运行 id，记录成功/失败分桶、完整成员键集合快照、逐成员结果（已归并/已隔离/已隔离·连带）、各账户余额前后值与失败原因；与捆记录、流水、隔离、余额同源。
- **按捆报告**：归并运行记录成功捆数/失败捆数/成员笔数与运行范围（散笔/按捆），互证报告按捆解释并交叉核对证明计数与捆状态。

| 接口 | 说明 |
| --- | --- |
| `POST /api/reversal-bundles` | 声明捆扎 `{bundle_key, entry_keys[]}` |
| `GET /api/reversal-bundles` / `/{bundle_key}` | 捆状态与不可变成员快照 |
| `POST /api/reversal-bundles/{bundle_key}/settle` | 按捆归并（整捆成败，全捆预检） |
| `GET /api/quarantine?bundle_key=` | 未平隔离按捆扎键过滤（坏捆成员全部可查） |
| `GET /api/settle-runs/{id}/bundle-proofs?bucket=` | 按归并运行 id 只读查捆分桶证明（可按成功捆/失败捆过滤） |
| `GET /api/bundle-proofs/failed` | 只读列出全部失败捆证明（未平隔离界面同源展示） |
| `POST /api/settle-runs` | 全量归并：散笔逐笔 + 待归捆按捆 |

## 界面约定

页面文案全部中文；入口：总览 / 账户 / 正向流水 / 冲正流水 / 归并台 / 未平隔离 / 净额互证。  
视觉：**左轨编号导航 + 右侧账册横线工作面**（Literata / JetBrains Mono，靛蓝强调）；**不是**交班台那种顶栏品牌+横向流程条。
